三步法：每个 Agent 工具都适用

通用的是方法，不是数字
STEP 1

定位本地日志

各家 runtime 都把 session 落在可预测的本地路径：~/.claude/projects/、~/.codex/sessions/、~/.zcode/cli/rollout/……零接入，不碰你的代码。

STEP 2

按 call id 去重

流式响应被拆成多条记录，每条带着同一份 usage。按 message.id 去重后，33 条记录还原成 11 次真实 API 调用。

STEP 3

拆成三个桶

fresh input（全价）/ cache_read（约 1/10 价）/ output——三桶分开，钱去哪了才第一次可见。混在一起的总数没有意义。

L1 · 自洽校验同 id 重复记录 usage 0 个不一致；上下文守恒校验暴露每调用 ±几百 token 的切分模糊——所以结论只下在量级上。
L2 · 账单对账金标准是供应商账单，不是任何日志工具。本次无账单可对，已在文中如实声明。
L3 · 版本锚定口径绑定 Claude Code v2.1.153 验证；runtime 升级即漂移，口径随版本重验。

敢说的，和不说的

结论只下在噪声之上
✓ 敢说（远超噪声量级）
  • ✓33 条记录 ≠ 11 次调用——重复记账让调用数虚高 3 倍
  • ✓输入流量的 89.3% 是缓存命中——866,560 tokens 走的是约 1/10 价的隐形通道
  • ✓冷启动 ≈ 全账单 30%——第一次调用为 66,609 tokens 付了全价
  • ✓单条 Bash 结果 ≈ 16%——一次 27,189 token 的大输出，就是隐形大单
✕ 不说（边界之内）
  • ✕单次调用的精确归因——缓存断点由系统决定，每处 ±几百 token 模糊
  • ✕行业分布——n=1，只声称这个 session 的结构
  • ✕美元金额——日志里没有钱；比价是假设，定价表按模型走
  • ✕未校准 runtime 的数字——口径只在 Claude Code v2.1.153 上验证

给工具作者

一份可执行的清单

id 去重、缓存拆分、版本锚定——三条全部可测试。照着做，你的工具就经得起评论区较真。

给数字本身

诚实作为方法

每个结论都标注噪声边界；说不出的结论就明说不出。在满是"trust me"的赛道里，这本身是稀缺品。

30 秒自测 · 跑在你自己的 ~/.claude/projects 上
python3 - <<'EOF'
import json, glob, os
calls = {}
for fp in glob.glob(os.path.expanduser('~/.claude/projects/*/*.jsonl')):
    for line in open(fp, encoding='utf-8'):
        try:
            r = json.loads(line)
        except ValueError:
            continue
        if r.get('type') != 'assistant':
            continue
        m = r.get('message') or {}
        u = m.get('usage')
        if not (m.get('id') and u):
            continue
        calls[m['id']] = u  # dedup by message.id
fresh = sum(u.get('input_tokens', 0) for u in calls.values())
cache = sum(u.get('cache_read_input_tokens', 0) for u in calls.values())
out   = sum(u.get('output_tokens', 0) for u in calls.values())
print(f"API calls: {len(calls)} | fresh: {fresh:,} | cache: {cache:,} ({cache/(fresh+cache):.0%}) | out: {out:,}")
EOF
